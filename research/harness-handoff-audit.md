## When a PR needs a shepherd

Today the loop assigns ready-for-pr, pr-review and ready-to-merge to the owner. Handoff prints the next command, and handoff wait observes local lane changes. GitHub can change while that lane stays unchanged. For an open non-draft PR, the classifier derives ready-to-merge from required bot states. It receives no CI or mergeability input, so CI or branch protection can still block merge. The missing input is whether a specific next action is possible now. [Loop and wait logic](../src/brain_train/core.mjs) · [PR classifier](../src/brain_train/pr-flow.mjs)

Start with a read-only command that answers “what needs my attention?” across the agent's lanes. Reuse the single-lane handoff show-next and pr status evidence. Apply that same decision in handoff output and the running loop. A cheap process can reconcile linked PRs on a bounded, backed-off timer while the loop runs. An optional GitHub event receiver can trigger the same reconciliation later. A stopped local process needs an explicitly configured host to wake an agent. Recording a reminder in a prompt cannot do that.

| Observed change | Who wakes and what they do |
| --- | --- |
| Current local head approved, ready-for-pr | Wake the owner once to open or link the PR and request the configured bots. |
| New actionable finding or failed required CI check on the current head | Wake the owner with the finding or failing job link. Route a code repair back through local review before requesting bot review again. |
| Checks or bot reviews still pending, an old head reports, or an unchanged draft is on hold | Continue lightweight reconciliation. A draft with an explicit hold date can wake the owner once the date arrives to reassess the hold. |
| Required reviews clear, required checks pass, and GitHub permits merge | Wake the authorized owner to merge under repo policy. Report an actionable conflict or required human decision to its responsible party once. |
| GitHub reports merged or closed | Reconcile with pr poll --apply and release locks through the normal transition. Routine bookkeeping can complete without a model turn. |

Show the lane, PR, observed head, responsible actor, reason, evidence link and next command in one short entry. Persist the observed event and its acknowledgement. Claim work atomically so concurrent Claude and Codex sessions cannot both act. Recheck eligibility before acting and retry an unacknowledged claim after expiry. Scope deduplication to the head, action and relevant finding or check run so a genuinely new failure on the same commit still wakes the owner. An unavailable owner can transfer shepherding through established lane authority. Reviewer fallback cannot grant merge permission.

Pilot on the three open PR patterns. A green CI result on #109 still leaves its bot-policy question. Current-head feedback on #110 calls for the owner. A pending draft hold on #108 needs one reassessment and no repeated prompts. Verify duplicate events, a missed event followed by reconciliation, a restart, stale-head notifications and a merge performed outside btrain. Measure actionable wakes, duplicate wakes and elapsed time from an actionable GitHub change to owner acknowledgement.

## One predictable lane monitor

The README presents two interfaces that both advertise lanes. The native btrain HUD shows repo-qualified lanes, ownership, status and locks across registered repos. AgentChatTR is a separate chat and agent-lifecycle service with its own lane panel. This makes the user's report of getting an unexpected dashboard plausible. The specific launch that produced it was not observed. [Native HUD and chat launch instructions](../README.md#agentchattr-multi-agent-chat) · [HUD lifecycle and health probe](../src/brain_train/dashboard.mjs)

Use the native HUD as the default for “show me the lanes”, “lane monitor” and “open the dashboard”. The existing command is `btrain dashboard open`. It discovers the running HUD or starts it and uses the actual URL, including when the preferred port is occupied. For a URL-only request use `btrain dashboard status`. Treat any request for terminal output as a lane status query. An explicit request for AgentChatTR can use its separate entry point. The user confirmed that the native btrain HUD is the intended monitor.

Put that instruction in the generated agent guidance and README. Mark chat integration optional in the architecture overview and remove it from the quick path for lane monitoring. Preserve explicit chat integrations for existing users. Separate background reconciliation from display: a claim, agent wake or status poll should not steal focus. Today's interactive claims can auto-open the HUD. `BTRAIN_DASHBOARD_AUTO_OPEN=false` already disables claim-time startup while leaving explicit opens available. Test with chat absent, an existing HUD, a busy default port, and multiple registered repos. A generic monitor request should open the native HUD once and launch zero chat processes. PR shepherding should also work with the browser closed.
