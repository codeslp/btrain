## What a local approval should establish

On main, runPrCreate checks for ready-for-pr. runPrRequestReview can post without the corresponding local approval check. Legacy transition L8 accepts a resolve by someone other than the recorded reviewer with an advisory. Lane A adds a shared check for outgoing bot requests, tightens PR-flow transitions, and routes repairs back through local review. A lane status alone cannot identify the commit a reviewer examined. [PR flow](../src/brain_train/pr-flow.mjs) · [Transition rules](../src/brain_train/transitions.mjs)

Prefer a reviewer from a different lab than the actual author. Today inferPeerReviewer excludes the owner and considers the requested reviewer, current reviewer and configured order. The configured Codex writer can therefore get a Codex reviewer while Claude is available. Record each runner's model lab independently of its collaborator alias. Preserve explicit human assignments. [Reviewer selection and dispatch](../src/brain_train/core.mjs) · [Runner configuration](../.btrain/project.toml)

Use the existing needs-review dispatch and lane state. Try the preferred lab first. On explicit quota exhaustion, immediately try the next eligible reviewer. On silence, use a configurable deadline refreshed by meaningful progress, with a bounded total attempt duration. If only the author's lab is available, use a fresh session and distinct reviewer identity. Exclude the author and prior authors. If nobody completes the review, retain needs-review and expose the retry action. A substantive request for changes returns to the author. Draft [spec 017](../specs/017-solo-mode-internal-review.md) provides the fresh-context precedent. Automatic per-lane fallback would require a spec change.

Give either harness the same lane, worktree, base and head SHAs, verification evidence, review asks and previous findings. Persist the active attempt and assigned reviewer before dispatch. Accept a verdict only if the attempt, reviewer and head still match. A new head invalidates approval. Ignore duplicate or late verdicts and recover an interrupted attempt on restart. Record fallback reason and observed reviewer identity. Recheck the approved head before PR creation or a bot review request on a repair. Keep local CLI availability and required GitHub bot policy separate. A GitHub quota failure can coexist with a working local reviewer. A stand-in for a required bot needs an explicit project policy.

Reuse the [task envelope](../src/brain_train/harness/task-envelope.mjs). Both installed CLIs advertise structured output. Give the adapters a small shared verdict schema with decision, findings and reviewed head. Separate process failures from completed reviews. The harness should bind the result to its recorded attempt and independently verify the checkout. ## Delivery and evaluation

The review-gate branch is the first correctness priority. Compact handoff output is the first independent cost improvement. Follow with evidence collection, targeted simplification and provider-aware routing. Exercise Claude-to-Codex and Codex-to-Claude review, quota exhaustion, silence followed by a late verdict, a new commit after approval, and restart during fallback. Check for one accepted local verdict on the current revision before PR creation or another bot request. Keep normal CI and repository merge requirements in force.

Compare like-sized lanes before and after each change. Measure bytes displayed per participant, elapsed time from code-ready to first local verdict, manual reassignments and returns for missing evidence. Track stale or premature approvals as correctness failures. Bytes and one-off wall times do not establish billed tokens or end-to-end savings.

Evidence included btrain CLI lane state, local code and specs, live GitHub reviews and checks, and vendor documentation. The focused reviewer-dispatch and PR-flow tests passed 82/82 on main.
